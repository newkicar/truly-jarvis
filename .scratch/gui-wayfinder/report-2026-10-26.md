## 二、框架选型（T-001）

**结论：PySide6（base 包，仅 QtWidgets；禁用 PySide6-Addons）+ Nuitka 打包（onedir + Inno Setup + 代码签名），与 deepagents harness 同进程共存。**

- **中文 IME = 硬淘汰维度**：Kivy（kivy#434 2012 Windows 中文 IME 失效、#8444 I18N 至今开放）、DearPyGui（#1571 输入 3~4 字符/秒、#2532 中日输入变 `?` 真实 bug）、Tkinter（SO 经典问题 11 年未根治）全部出局；Qt Windows 原生 IME（组合输入事件）成熟，开箱可用。
- **Markdown 流式**：QTextBrowser/QTextEdit 自 Qt 5.14 起原生 Markdown；append 式增量追加 + 尾部自动滚动（钉底），避免全量重绘；代码高亮用 QSyntaxHighlighter（官方自带 highlighters）。
- **拖选/复制/右键菜单**：Qt 原生零成本。
- **打包与杀软误报**：Nuitka standalone 社区实测 Qt 应用 ~40MB 单 exe；Nuitka 误报率显著低于 PyInstaller（PyInstaller 官方 issue #6754：误报根因 = 其 bootloader 是恶意软件共性组件）；**代码签名（OV/EV）是根治项**，发布附 SHA-256 + VirusTotal 自查流程。发布形态 = Nuitka onedir 目录 + Inno Setup 安装包（与 Jan/ChatBox/LM Studio 实际发布姿势一致）；onefile 不推荐（自解压启动慢，有 >1min 极端案例，体积收益有限）。
- **许可**：PySide6 base = LGPLv3；Qt 官方许可变更页截至 6.12 **无 GPLv3 迁移**，LGPL/AGPL 结构未变；AGPL 风险集中在 PySide6-Addons（QtQuick/QtWebEngine），**不依赖该包即无传染**。规避 LGPL 静态链接「提供目标文件」义务：Qt DLL 与 exe 同目录动态共存；本场景无 SaaS 分发，义务面很小，发布前过一道法务确认。
- **测试**：pytest-qt 官方支持 PySide6，Windows 可 `offscreen` 无头测试；逻辑层 200+ 既有单测原样复用。
- **C#/Rust 宿主 + Python 边界**（pyo3 内嵌 / PyOxidizer / Tauri sidecar / pythonnet）技术成熟但双语言维护成本翻倍 → **列 P2 本期不做**（先例：Jan v0.6.0 Electron→Tauri 演进）。
- **先例池**（可抄要点）：LM Studio（「GUI 宿主 + 独立高性能引擎」分层、本地 server OpenAI 兼容 REST+SSE）· Jan（本地 LLM + 内嵌 runtime、可独立 server 化、store.json 损坏可删重建）· ChatBox（用户自配 OpenAI 兼容端点/密钥的设置模型，与 Jarvis「LLM 各人自配」完全同构；userData 与安装目录分离 + config 校验/备份双文件）· AnythingLLM（桌面+服务端双形态、自带 RAG 捆绑方式）。
- **落地前实证清单（喂 T-006）**：① Windows 中文 IME 进 QLineEdit/QPlainTextEdit（含自绘补全弹层上的组合窗定位）② QTextBrowser 流式 Markdown 追加（未闭合代码块/表格的增量解析策略）③ 选区复制 + 右键菜单 ④ Nuitka 打包 + 签名 + VT 自查 ⑤ PySide6 × Python 3.12 wheel 兼容性 ⑥ Credential Manager 组策略限制场景。
- **风险**：杀软误报（签名 + 发布渠道教育是必配，非可选项）；Nuitka 编译分钟级（CI 需缓存 C 扩展产物）；RAG 依赖 chromadb 会带入 onnxruntime 等 100MB+ 原生大包 → 基础 exe 不捆（与遗留 (c) 联动）。
## 三、LLM 用户自配（T-003）

- **配置层分离**：新增用户全局 `%APPDATA%\Jarvis\config.json`（与安装目录分离，升级/重装不覆盖；多用户机器天然隔离；沿用 `JARVIS_HOME` 覆盖语义）。Chatbox 式损坏自愈：config 非法 → 自动回退最近 `config-backup-*.json`；`version` 字段 + 单调迁移器。现有 `jarvis.json`（项目级）保留，`model` 段从 `{base_url_env, api_key_env, model_id_env}` 升格为 `{"provider": "company"}`（钉住本项目用哪个 L1 provider；缺省 = `default_provider`）；旧 `*_env` 键保留一个版本兼容读路径（随 T-005 共存策略定迁移时间表）。
- **密钥存储 = 最高档先例（Continue）**：config 只存 `key_ref`（如 `jarvis:company:api-key`）不落明文；实现 = Python `keyring` 库 → **Windows Credential Manager**（纯 ctypes、无原生依赖、零安装；用户级条目天然多用户隔离；机器级 vs 用户级默认用户级）。备选演进档 = Continue 式 AES-256-GCM 本地密文 + Credential Manager 存主密钥（为跨机备份/同步留路，P2）。本地推理端点（LM Studio `localhost:1234` / Ollama / Jan）= `sk-no-key` 占位。读取时序：启动读 config.json → 按 `key_ref` 从 Credential Manager 取 key → 注入 `ChatOpenAI(base_url, api_key, model)`（`.env` 三件套的运行时等价物）。
- **端点探测（抄 Jan 五档）**：保存 provider 时自动 `GET {base}/models`（8s 超时）：
  | 状态 | 面向非程序员的文案 | 自动动作 |
  |---|---|---|
  | OK | 连接成功 | 填充模型下拉 |
  | 401 | 密钥无效 | 提示改 key；多 key 时轮换 |
  | 403 | 无访问权限 | 提示找管理员开权限 |
  | 429 | 限流 | 提示稍后重试 |
  | 网络错误 | 连不上服务 | 检查网络/服务是否启动（connection refused 专条） |
  | 404 | URL 缺 `/v1` | 提示 base_url 通常以 /v1 结尾 |
  `probe_supported: false`（内网网关未实现 /models）：允许手填 model id，保存成功不算失败（Jan 原语义）；列表为空也提示手填。
- **首启向导 5 步、可跳过**（LM Studio「先跑起来、后配远端」哲学）：① 欢迎 + 安全承诺（配置在本机、密钥进系统凭据管理器、不上送任何服务器——抄 Chatbox FAQ 文案）② 选 provider 类别（公司内网 OpenAI 兼容 / OpenAI 官方 / 本地 LM Studio·Ollama·Jan）③ 填 base_url + API key（本地类走 `sk-no-key`/空 key 占位）④ 测试连接（不通过可存为草稿）⑤ 选默认模型。产物 = config.json + Credential Manager 条目，幂等可重入。
- **工具类密钥**：TAVILY_KEY/SOK_* 同理迁 `tool_keys` refs；`mcps.servers` 的 `env` 字段可选支持 `{"from_credential": "jarvis:mcp:<name>"}` 引用形式（P1+）。
- **风险**：域账号组策略禁 Credential Manager 写入（办公 Windows 90%+ 场景允许【离线推断】）→ 降级 DPAPI user-scope（`crypt32.CryptProtectData`，同样不落明文）；key_ref 悬空（凭据条目丢失/域账号重置）→ 启动校验可达性，缺失即回向导第 3 步，不崩；Nuitka onedir 装 Program Files（只读）+ config 在 %APPDATA%（可写）——路径分离天然成立，首启全部写入不得碰安装目录。
## 四、runtime/UI 解耦（T-002）

**所有先例收敛到同一形状：runtime 单实例 + UI 只是客户端 + 一套协议承载「事件流 / 会话线程 / 审批决策」三流。**

- **L1 事件层**：在 `streaming.py` 之上加「协议投影」——v3 事件投影为 opencode 式三段式 `{id, type, properties}`（type 点分层：`message.part.delta` / `message.part.updated` / `session.status` / `todo.updated` / `permission.asked` / `permission.replied`），首事件 `server.connected` 作连接标记，断线/启动 **bootstrap replay**（拉全量历史事件重放重建初态，再切 live）；`streaming.py` 内核（韧性四期熔断、SanitizeHistory、finalize_turn、drain 看门狗）**零改动**。TUI 与 GUI 都消费投影后事件，不再直连 `stream_events` 原始形态。
- **HITL 转递（codex 式 server→client 反向请求）**：审批是一个 pending 对象（工具名 + 参数 + thread_id），GUI 渲染卡片后决策经专用回写通道进 langchain `{"decisions": [...]}` resume 契约——permissions.py 全工具 approve/reject/edit 三决策（tui-ux11 已落地）与 tui-ux12 YOLO **零改内核**。多中断并发 = FIFO 排队一次显一个（codex `InterruptManager` ≈ tui-ux7 thread 级 turn-gate，语义同构直接升格为协议语义）。
- **L2 会话层**：thread_id 打标每个事件；thread CRUD / 全量状态批量 / fork / abort / diff / revert 镜像 opencode session API，落到 `commands.py` 既有 `/sessions /history /replay /fork /rollback /undo`，**协议化不改逻辑**；**SqliteSaver（checkpointer）是唯一真相源**，UI 本地 store 可随时重建（复用 `streaming.py` replay 快路径）；`sched-*` 线程协议层过滤（沿用 CLI 展示约定：`/sessions` 隐藏 + 自动 `delete_thread`）。会话切换 = 换订阅 thread，**不重建 runtime**。
- **L3 审批 GUI 表达 = 卡片 + 表单 + diff 三件套**：
  | 工具 | 卡片 | 编辑表达 |
  |---|---|---|
  | execute | 命令预览（只读高亮） | 单行编辑框（Windows 多行命令已被 shell_backend 预拦截，单行即合规边界） |
  | write_file / edit_file | **diff 预览**（write 全量 / edit unified diff） | 参数表单（路径可改） |
  | delete | 极简确认卡（路径 + 后果说明） | — |
  编辑参数交互对齐 TUI 经验十「看得见改」（原值只读展示行 + 编辑框，提交 = langchain `edit` 决策，tool_call id 保留、args 改写；1.3.x/1.4.x 双存储形式兼容见 tui-ux12 测试经验）。「永久放行」= opencode `remember` 语义 → 复用 `commands.always_approve` / `approve_prefix` 命令前缀规则（回写 jarvis.json），GUI 只是渲染入口；YOLO 线程级免审批在 GUI 同样生效（Header 状态位 `[YOLO]` 镜像）。
- **单机 exe 传输**：codex app-server 的 **in-process bounded channel** 先例（「replaces socket/stdio transports with bounded in-memory channels... preserving app-server semantics」，背压 = try_send → WouldBlock）——同一协议三种 transport（stdio / WebSocket / in-process），本期 exe 走 in-process（UI 线程 ↔ runtime 线程直接对话，免进程边界）；协议 shape 预留 transport 可换，未来 `--serve` 多客户端形态只加 transport 不改协议（P2）。
- **不照抄 / 降优先级**：opencode `POST /message` 同步阻塞通道（GUI 一律 async + 事件流）；`--serve` 多客户端 / remote-control 配对码（P2）；LangSmith `ui.push()` generative UI 自定义事件推送（P2，`onCustomEvent` 通道预留）。
- **代价**：官方 `useStream` 四套 binding 全绑 web 框架（React/Vue/Svelte/Angular），PySide6 无等价物 → 需自写薄响应层（Qt 信号槽 + 事件 reducer，形状参考 opencode `event-reducer.ts` + bootstrap replay），约 200~400 行【离线推断：无官方 Python desktop binding 先例】。

  - `streaming.py`：`run_agent_turn`（参数全是 callable，无一 UI 类型；内部 50ms drain 看门狗 / GraphDrained / force_handoff）· `consume_stream_events`（StreamCallbacks 5 键：on_subagent / on_tool_call / on_message_delta / on_message_end / on_status）· `collect_interrupt_decisions`（逐条中断收集 → `{"decisions": [...]}` 或 None 放弃本轮）· `cli_prompt_action`（第一参考实现，返回与 modal 同构 dict）· `decision_from_choice` / `interrupt_action_key` / `filter_pending_interrupts` / `format_agent_error` / `iter_text_deltas`（纯函数）。
  - `commands.py`：60+ 纯逻辑符号（`thread_config` L23 唯一出处含 `checkpoint_ns: ""`、`dispatch_command`、`finalize_turn`/`turn_needs_finalize`/`channel_values_stuck`、`force_handoff`、`undo`/`fork`/`prepare_replay`/`repair_stuck_thread`、`yolo_command_text`、`always_approve`、`build_submission`、`render_session_text`/`list_sessions`、`format_doctor_report`、`first_human_text`）。
  - `permissions.py`（GATED_TOOLS / `build_permission_interrupts` → `(interrupt_on, state)` / `apply_permission_override` / `approve_prefix` / yolo 三件套 / PermissionDenyMiddleware；state 按引用共享、live 生效）· `agent.py::build_agent`（L280）· `resilience.py` 全中间件（graph 内部，客户端无关）· `jump_in_queue.py` / `scheduler.py` / `mcps.py`（进程内，跨进程注意见风险）· `tui_format.py`（头注「CLI+TUI 共用纯函数」，GUI 可借用消息排版或弃用自带渲染）。
- **HITL 契约闭环（工单点名项）**：`collect_interrupt_decisions(ask_action)` 只要求 `ask_action: inv → dict|None`；TUI modal 与 CLI 返回**同构 dict**（docstring 原文「返回 modal 同构结果 dict」），最终形状 `{"decisions": [...]}` 交 langgraph 原生 `Command(resume=)`。**GUI 只需新增第三个 `ask_action` 实现**，对话框按钮可比 TUI 少（MVP：放行/拒绝/编辑参数），契约形状不变。
- **新增 `src/gui/` 4 文件**（全部是「照抄 tui 形状、换事件泵」的平移，不是对既有代码的重构）：
  1. `gui_presenter.py`：TurnPresenter 同构——唯一替换 ≈20 处 `app.call_from_thread(fn, *a)`（Textual 耦合核心）→ Qt `signal.emit(fn, a)` + 事件循环，或 `queue.Queue` + 主线程 `app.after`；`callbacks()` / `handle_interrupts` 签名不变。
  2. `gui_hitl.py`：`gui_prompt_action(inv, *, permission_state, on_always_approve, …)` 第三 ask_action——GUI 审批卡片（对标 codex desktop）打开 → worker 线程 `threading.Event.wait()` 阻塞 → 对话框关闭 set 并取按钮选择 → 经 `decision_from_choice` 出 dict。契约与 modal/CLI 完全同构。
  3. `gui_turn_gate.py`：纯 Python 回合门——`set[thread_id]` 门 + 每 thread 消息 FIFO `deque`，门释放（presenter finally 等价点）经 GUI 主线程重投递。目的 = 避免 tui-ux7 修复过的同一根因（同 thread 双 graph 并发 → SqliteSaver 锁竞争 + finalize_turn 交错）。不碰 tui.py。
  4. `gui_main.py`：装配段照抄 `main.py`：load_config → load_mcp_tools → `SqliteSaver.from_conn_string` → build_permission_interrupts → build_agent → JumpInRegistry → make_scheduler → PySide6 事件循环。
- **划出边界、不迁移（Textual 专属 6 文件保持原样）**：`tui.py` / `tui_turn.py` / `tui_log.py` / `tui_punct.py` / `ime_shim.py` / `input_probe.py`。GUI 中文 IME 走 Qt 原生（T-001 已实证达标），**不需要** ime_shim（ConPTY 专用）。
- **架构 A / B**：**A（MVP 推荐）GUI 进程内跑 graph**——主线程 = Qt 事件循环；每 thread 一个 worker 线程跑 `run_agent_turn`（与 TUI `@work(thread=True)` 同构）；事件通道 = 复用 5 键 StreamCallbacks + `run_agent_turn` 4 个 `on_*` 参数，**不发明新协议**；优点 = 与 TUI 行为逐项对齐（既有 200+ 单测语义直接覆盖 commands/streaming 层）、零跨进程风险。**B（升级路径）独立 runtime worker 进程**——`python -m src.gui_runtime` 子进程 + 现有 5 回调序列化为进程间消息（stdin/pipe JSON 行或本地 TCP），审批反向通道 = 子进程阻塞在 `ask_action` 时向父进程发 `{interrupts}`、父进程回 `{"decisions": [...]}`。收益：GUI 崩溃不杀图执行、多窗口共享一个 runtime、SqliteSaver 单写者。**先 A 后 B：A 的回调形状就是 B 的线协议，不推倒重来。**
- **官方 seam 核查（红线项）**：docs-langchain 确认 `stream_events` 事件契约（event-streaming 页）与 HITL interrupt/resume（`Command(resume=…）`）即本项目 `run_agent_turn` 已落地的官方契约本身——**无需给 deepagents/langgraph 加任何新钩子/middleware**。
- **已知风险（T-004 原文）**：① SqliteSaver 双客户端锁竞争（TUI+GUI 并发写同一 checkpoint db = SQLITE_BUSY；WAL 读并行写串行，busy_timeout 行为未实测 → (d) 裁定项）；② `permission_state["thread_id"]` 可被并发 sched-turn 覆写（fail-safe 方向，A 模式放大该窗口、B 免疫；加固 = 按 thread 分桶，T-005 裁定后选项）；③ always_approve 三写者 jarvis.json 版本分叉窗口（MVP 单 GUI 主窗口可接受；B 方案 runtime 独占写 + 客户端只读）；④ YOLO `state["yolo_threads"]` 纯进程内内存（A 模式 TUI/GUI 各自 app 实例互不感知——语义可接受，`/yolo` 本就是 app 内设计；跨进程天然一致）；⑤ JumpInRegistry / make_scheduler 不跨进程（TUI+GUI 同开 = 双 scheduler 重复执行 `sched-*` → 后启动者检测到 runtime 已存在则不 start scheduler）；⑥ HITL 等待期「取消」语义：关闭审批对话框 = 回 None = 放弃本轮（与 modal `q 放弃` 一致，drain 不生效因为 interrupt 在图外）→ GUI 对话框文案必须标注，避免用户以为关窗 = 取消执行。

## 七、遗留裁定（spec 阶段定案，三项）

- **(b) 小白默认值**：是否隐藏命令面板 / 审批按钮放大 / 工具调用折叠——结合 T-002 审批卡片先例在 spec 定。
- **(c) 可选依赖降级**：RAG（Ollama `bge-small-zh-v1.5` embedding + chromadb）不入基础 exe（chromadb 会带入 onnxruntime 等原生大包，体积可能 100MB+ 级）；缺失时自动回落（与 AGENTS.md「Ollama 不可用自动回落」语义一致），需要时引导用户装 wheel 或外部 Ollama 服务；**定时任务同列可选**（GUI 主程序未启用时不跑 scheduler）。
- **(d) 同机 GUI/TUI 并发模型 + SqliteSaver 锁**：单 app 内 TUI/GUI **共享同一 runtime 实例与 checkpointer**（同进程，不各开连接）；后启动者检测到 runtime 已存在则**不 start scheduler**、JumpIn 只在本进程生效；conn string 加 `busy_timeout` / WAL pragma（同 thread 不同客户端串行由回合门保证本进程内串行）；跨进程多客户端 = P2 单写者模型。
- **T-006 实证清单**：IME 弹层定位 · 流式 MD 解析策略（token 级增量解析器 vs 每 N token 全量重渲染 QSyntaxHighlighter）· 选区复制 + Nuitka + 签名 + VT · PySide6 × Python 3.12 wheel 兼容性 · Credential Manager 组策略。
