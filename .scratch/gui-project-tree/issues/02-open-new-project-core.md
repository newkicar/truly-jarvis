# 02 — 打开 / 新建 项目内核（缺 jarvis.json 三分支 + 建目录骨架）

**What to build:** 「打开项目」和「新建项目」两个动作的**纯内核**：给定一个目录 / 一个(名+父目录)，决定「开哪个项目根、要不要初始化」，然后登记进注册表并设为活动。不碰 GUI，不做 runtime 切换（那是票 03）。对非程序员要省心——选个文件夹就能开，缺配置时只补骨架、绝不覆盖已有。

**Blocked by:** 01（需要注册表登记/去重/置顶）

**Status:** ready-for-agent

## 打开项目判定（纯函数，给定所选目录）
- ① 目录本身有 `jarvis.json` → 开它。
- ② 本身没有、但**上级**有（复用既有 `discover_project_root` 向上找逻辑）→ 开那个上级项目根。
- ③ 都没有 → 返回「需初始化」决策；上层弹**一次确认**，同意后跑**幂等骨架**（只补缺的默认 `jarvis.json` + 空 `schedules/`、惰性 `checkpoints/`，**不覆盖**任何已有文件）再开。
- 重开已在注册表里的路径 = 只刷新 `last_opened`、不重复加（呼应 01 去重）。

## 新建项目
- 在所选**父目录**下建 `<父目录>/<项目名>/`（项目名必填），跑同一套幂等骨架，登记 + 设为活动。
- 显示名 = 项目名（可后续在 04 里右键改）。
- 创建时**不配知识库/记忆**：知识库默认无 `/vault/`，记忆走全局；**不**把 `memory_dir` 指回项目里。

## 验收
- [ ] 三分支判定各给一例单测（本身有 / 上级有 / 都没有），返回的「项目根 + 是否需 init」符合预期。
- [ ] 幂等骨架：对着已含 `jarvis.json` 的目录跑不改动它；对空目录补齐默认且不误删。
- [ ] 打开/新建后注册表出现该条目且 `active` 指向它；重开不产生重复条目。
- [ ] 新建在父目录下正确建出 `<父>/<名>/`。
- [ ] 决策/登记是纯逻辑，可用假注册表 + 临时目录单测（受管目录，禁用 tmp_path）。

## 非目标
- 不做「切过去」的 runtime 关闭/重建（票 03）。
- 不做文件夹选择器/对话框的 Qt 接线（票 05）。
- 不做建项目时配知识库/记忆的入口（Out of Scope，后续「项目设置」）。
