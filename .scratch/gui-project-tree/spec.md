# JARVIS GUI — 多项目工作区（项目树 + 打开/新建项目）

**Status:** ready-for-agent

## Problem Statement

JARVIS GUI 现在一个实例 = 一个项目（一个 `project_root` = 一个 runtime：agent + checkpointer + 调度器 + 权限态 + 插队缓存）。会话侧栏是**平铺列表**，只显示当前这一个项目的会话。用户换了个代码库/工作区就没法在同一个窗口里继续：既不能把「项目 A 的对话」和「项目 B 的对话」并排看到，也没有「打开一个文件夹」「新建一个项目」的入口。对非程序员用户，要手动改 `JARVIS_PROJECT_ROOT`/重启才能换项目，负担太重。用户想要一个像 ChatGPT Projects / 编辑器「最近项目」那样的**多项目工作区**：侧栏按「项目 → 会话」成树，能打开/新建项目，能一眼看到自己在哪个项目。

## Solution

把侧栏升级成**项目 → 会话**两层树，并给主窗口加上「打开项目 / 新建项目」入口，形成一个多项目工作区：

- 侧栏：顶层是「项目」分组，每个项目是一个节点（点**项目名**=切进该项目；`+/−`=展开/收起它的会话列表），项目下挂它的会话（短名 + 活动/置顶/运行/归档标记）。
- 两个新菜单：**打开项目**（最近项目列表 + 打开文件夹…）与 **新建项目**（输入名字 + 选位置）。
- **同一时刻只有一个活动项目**：切项目 = 关掉当前 runtime、为目标项目重建、打开它上次活动的那条会话（避免挂 N 套 runtime，也守住「单调度器」不变量）。
- 启动 = 打开**最近打开**的项目；空注册表 = 空状态 + 「打开/新建项目」两个引导按钮。
- 全局一份**项目注册表**（`~/.jarvis/projects.json`）只放导航/记账；每个项目自己的**会话历史、知识库、指令、定时任务**仍留在项目文件夹里（自包含、可整体搬走）；**长期记忆仍全局**（`~/.jarvis`，现状默认，不动）。

## User Stories

1. As a 用户, I want 会话侧栏按「项目 → 会话」成树，so that 我能看清每条对话属于哪个项目。
2. As a 用户, I want 用「打开项目」选一个文件夹作为项目，so that 我不出窗口就能开一个新代码库工作。
3. As a 用户, I want 用「新建项目」给一个项目起名并选个位置，so that 我能从零开始一个新项目。
4. As a 用户, I want 应用启动时直接打开我最近用的项目，so that 我接上次的地方继续。
5. As a 用户, I want 打开一个没有 jarvis.json 的目录时被问一次「要初始化它吗」，so that 我不必手写配置文件。
6. As a 用户, I want 「打开项目」下拉里列出最近打开过的项目，so that 我一键就能跳回。
7. As a 用户, I want 点某个项目的名字就切进它，so that 应用为该项目重建并显示它的会话。
8. As a 用户, I want 侧栏能列出某个非活动项目的会话名而不用完整加载它，so that 侧栏保持轻。
9. As a 用户, I want 应用记住每个项目我上次用的是哪条会话，so that 切回去时自动打开那条。
10. As a 用户, I want 切走时若当前项目有回合在跑就弹一次确认，so that 我不误伤进行中的工作。
11. As a 用户, I want 把一个项目置顶到列表顶部，so that 我常做的项目始终显眼（置顶只改顺序、不加上下文）。
12. As a 用户, I want 在侧栏给项目改个更顺口的显示名，so that 不必用文件夹原名。
13. As a 用户, I want 把项目从列表移除（不删它的项目文件），so that 我能给侧栏减负且随时重新打开。
14. As a 用户, I want 从项目菜单直接跳到它的文件夹（资源管理器），so that 我能查它盘上的文件。
15. As a 用户, I want 标题栏显示活动项目的名字，so that 我随时知道自己在哪个项目。
16. As a 用户, I want 状态行显示「活动项目 · 当前会话」，so that 我能确认当前上下文。
17. As a 用户, I want 没有项目时看到「打开/新建项目」的空状态引导，so that 我知道怎么起步。
18. As a 用户, I want 会话的右键菜单（分享/下载/重命名/置顶/克隆/归档/删除）在树的叶子节点上继续可用，so that 既有能力不丢。
19. As a 用户, I want 长期记忆在所有项目间共享（`~/.jarvis`），so that 我的偏好处处生效。
20. As a 用户, I want 每个项目的会话历史/知识/指令/定时任务都留在它自己的文件夹里，so that 一个项目自包含、可整体搬走。
21. As a 用户, I want 切项目时线程级的 YOLO 免审批自动重置（新线程），so that 我不把免审批串到别的项目。
22. As a 用户, I want 「＋ 新会话」在当前活动项目下新建会话，so that 它在多项目下也做对事。
23. As a 用户, I want 菜单栏新增 打开项目/新建项目、同时保留 命令/主题/时间旅行/MCP 工具/定时任务/高级，so that 既有入口不丢。
24. As a 用户, I want 打开一个已在列表里的文件夹不产生重复条目，so that 列表保持干净。
25. As a 用户, I want 最近那个项目的文件夹被删/移动时，启动跳过它、取下一个仍存在的；全没有就落回空状态，so that 应用不会崩。

## Implementation Decisions

- **单活动项目**：应用同一时刻只持有一个 runtime（agent + checkpointer + 单一调度器 + 权限态 + 插队缓存）。切项目 = 关闭当前 runtime、为目标项目根**重建**一个新 runtime、重连 UI。刻意**不**做「N 个项目同时开着」——那会挂 N 套 checkpoint 库/调度器/子代理栈，破坏单调度器不变量并吃内存（Cursor 也是「按 workspace 隔离、单开」）。
- **全局项目注册表**：持久化在用户主目录（`~/.jarvis`）下的 `projects.json`，只做导航/记账。模式（原型定案，唯一内联的形状）：
  ```
  { "active": "<项目绝对路径>",
    "projects": [
      { "path": "<已解析绝对路径>", "name": "<显示名>", "pinned": false,
        "last_opened": <epoch>, "last_active_thread": "<thread-id 或 null>" }
    ] }
  ```
- **注册表操作是纯逻辑、独立可测**：加入（按**已解析绝对路径去重**）、按「置顶优先 + 最近打开降序」排、置顶、改名、**移除（只删注册表项，永不删项目文件）**、启动选取（取最近且路径仍存在的；跳过错过的；没有则空状态）。
- **打开项目判定（纯函数）**：给定所选目录 → ① 目录本身有 `jarvis.json` → 开它；② 本身没有但**上级**有 → 认定属于那个上级项目根、开它；③ 都没有 → **弹一次确认**后做**幂等**骨架（只补缺的默认 `jarvis.json` + 空 `schedules/`，惰性 `checkpoints/`，**绝不覆盖**已有文件）再开。重开已在列表里的路径 = 只刷新最近、不重复加。
- **新建项目**：在所选**父目录**下建 `<父目录>/<项目名>/`，跑同一套幂等骨架，登记并设为活动。知识库**不在此配**（默认无 `/vault/`），记忆走全局。
- **数据归属（本功能不改语义，仅落实）**：会话历史（checkpoint 库 + 其 wal/shm 侧车）、`sessions.json`、项目指令、知识库、定时任务 **全在项目文件夹**；**长期记忆保持全局**（本就默认 `~/.jarvis`，新建/打开项目都不把 `memory_dir` 指回项目里）。
- **非活动项目的会话名只读列出**：从该项目自己的 `sessions.json`（短名表）读，**不**加载它的 runtime（呼应单活动项目）；该项目被设为活动后，live 会话列表为准并校正显示。
- **切项目**：若当前项目有进行中回合 → 弹确认「切换将取消当前项目的进行中回合」。切后打开目标项目的上次活动会话（`last_active_thread`），没有就开一条新会话。「＋ 新会话」与会话右键菜单都作用于**活动项目**。
- **侧栏树**：项目行 = 目的地（点名字=切进该项目）；`+/−` 仅展开/收起其会话列表。项目行右键：改名 / 置顶 / 资源管理器打开 / 移除（只删登记）。会话叶子右键：沿用现有 分享/下载/改名/置顶/克隆/归档/删除。活动/置顶/运行/归档标记沿用平铺列表的做法。展开/收起状态记在 UI 偏好（默认展开活动项目）；注册表变大时列表直接滚动，先不做「更多」折叠。
- **菜单栏**：新增「打开项目」（最近列表 + 打开文件夹…）与「新建项目」（新建…，以后可加模板）两个下拉；保留既有菜单。最终顺序：`打开项目 | 新建项目 | 命令 | 主题 | 时间旅行 | MCP 工具 | 定时任务 | 高级`。
- **标题/状态**：标题栏 = `JARVIS — <活动项目显示名>`（模型名降级到状态区/主题区；空状态 = `JARVIS`）；状态行 = `<活动项目> · 会话 <短名或 id>`（有回合在跑接 `…`）。
- **启动**：打开最近登记的项目及其上次活动会话；空注册表 → 空状态引导（打开/新建两个按钮），**不**偷造默认 scratch 项目。

## Testing Decisions

只测**外部行为**（注册表文件内容、哪个项目成了活动、树的节点集合、标题/状态串），不测 widget 内部私有属性名（沿用现有 GUI 测试已用的稳定公开句柄）。三个接缝（尽量取最高、复用既有）：

- **注册表接缝（纯模块）**：schema 往返、去重、排序/置顶、移除=仅注册表、启动选取跳过错项、空状态。先例：`test_gui_session_registry.py`。
- **工作区/切换接缝（用假 runtime/builder 驱动）**：打开项目三分支判定、新建=建目录+骨架+登记、切项目（取消进行中回合的确认 + 恢复 `last_active_thread` + 只读从 sessions.json 取非活动项目会话名）。先例：`test_gui_presenter.py` / `test_gui_assembly.py`。
- **GUI 接缝（offscreen MainWindow，monkeypatch 掉 runtime 切换器以不碰真模型）**：树结构 + 点项目名切换 + 点叶子 + 右键菜单；打开/新建菜单接线；标题/状态串；空状态。先例：`test_gui_session_menu.py` / `test_gui_smoke.py` / `test_gui_ticket10.py`。

约束：offscreen 平台；**禁用 tmp_path**（用受管自建目录）；不引入新的 Qt 依赖。

## Out of Scope

- 跨项目**全局搜索**会话（后续增强：只读打开各项目 checkpoint 库、或建全局索引）。
- 建项目时**配知识库/记忆**（后续给「项目设置」入口再配）。
- **多项目同时打开**（N 套活 runtime）。
- 把会话历史或项目级数据**挪到全局**（刻意留在项目里）。
- 注册表的**多用户/共享/云同步**。
- 项目列表的**拖拽排序**（排序只按 置顶 + 最近）。

## Further Notes

- **先例**：ChatGPT Projects（同一时刻一个活动项目；pin 只改顺序；官方教训「项目应是目的地、不只是折叠钮」——我们让「点项目名=切进」落实这条）；Cursor（聊天历史按 workspace 隔离、单开；印证「单活动项目 + 数据留在各项目盘上」的取向）。
- **两条分立的持久化**：注册表 = 导航/记账（`~/.jarvis`）；项目文件夹 = 真正的工作区。把项目从注册表移除**永不**删它的文件（checkpoint/知识/会话留在盘上，选一次文件夹就能再打开）。
- 数据归属这条（记忆全局 / 会话·知识·指令·定时项目级）本功能**不改变**既有默认，只是把「多项目」这套新 UI 落在它上面。
