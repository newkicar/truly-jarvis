## 新功能：空格+/ 任意位置命令补全（tui-ux23，TUI+GUI 共享内核）
- **行为**：`/` 不再要求行首——光标所在行内，`/` 位于行首或前导空白后即可弹出命令补全（第一行与续行一致，TUI 多行输入框任意位置可用）；
- **内核**（d1b6fdd）：`slash_completion.slash_query` 改 rfind 定位——取光标行最后一个 `/`，其前一字符为行首或空白才触发（`abc/`、`file://` 等词中/URL 斜杠不触发）；query = `/` 后至首个空格为止；`tui_completion.resolve_overlay_state` at_index 指向真实 `/` 位、去掉 cursor-end 守卫，Tab 接受只替换自真实 `/` 起、经 `line_projection` 只改光标行；
- **GUI 零改动**：`src/gui/completion.py` 自工单 10 起走同一 `tui_completion` 内核（`resolve_for_input` → `line_projection`），本批 GUI 侧无代码变更；
- 测试 +16（test_slash_completion 触发/非触发边界、query 截断）+ 80（test_tui_completion 多行/中位/Tab 替换范围）。

## 修复：GUI 续行 `@`/`/` 光标失步（gui-ux24）
- 用户复报「只要换行，@ 和 / 就都不好使」——Shift+Enter 续行后在续行敲 `@`/空格+`/` 均不触发补全弹层。
- 根因（真实 Windows 探针实证；offscreen 平台无此怪癖、纯内核回归测试拦不住）：`QPlainTextEdit` Shift+Enter 换行后 `textCursor().blockNumber()` 误报 0、`positionInBlock()` 返回**绝对**文档位置 → 旧 `rowcol_from_cursor` 把续行当成第一行 → 续行 `@`/`/` 永远不触发（`tui_completion` 内核只认行投影，零改动）。
- 修复（3f38a0b，`src/gui/completion.py` 唯一读点；`resolve_for_input`/`accept_suggestion`/`has_query_no_match` 三路共用）：`rowcol_from_cursor` 改**位置式推导**——`row = text.count('\n', 0, pos)`、`col = pos - text.rfind('\n', 0, pos) - 1`，不读 blockNumber/positionInBlock，CJK 安全。TUI 侧（单行 `JarvisTextArea` + `_continuation` 栈，`cursor_location` 与 `text` 同源）确认无此类失步。
- 测试：`tests/test_gui_ticket10.py` +3（`_DesyncEdit` 假 widget：toPlainText 正确 + blockNumber 恒 0 / positionInBlock=绝对位置 → 失步免疫 / 续行 @ / resolve / has_query_no_match 三断言）；该文件 25/25、定向 14 文件 288 过、全量 1300 过 + 3 失败（预存 test_config×3，零新增失败）。

## Side 会话 per-thread 隔离（side-isolation，对标 codex）
- **根因**：`open_side` 写共享全局键 `permission_state["mode"]`（整 app 一份）→ side 打开期间切回主线，主线 write/edit/delete 也被 Plan 门拦；
- **修复**（beaa891）：`plan_mode.effective_mode(state, thread_id)`——side 线程成员即强制 plan（只读），否则取全局 mode；`PlanModeMiddleware` 按当轮 thread 判定，**全局 mode 键全程不动**；`commands.open_side/close_side` 删除模式快照/恢复（`SIDE_MODE_BEFORE_KEY` 移除，全仓 0 引用）；TUI/GUI 模式徽章改按当前 thread 解析（全局 Tab/Shift+Tab 切换语义不变，仍改全局键）；
- **效果**：side 会话对主线零影响——主线 Act 写工具可用、只读守卫只作用于 side 线程；`/side close` 即删线，无残留；
- 测试：test_side 重写（open/close 断言改 `assert "mode" not in state` + 核心隔离用例 test_side_thread_write_blocked_mainline_unaffected：side 线程写工具被拦、主线写工具不受影响）+ test_plan_mode +2（effective_mode）；定向 113 过。
