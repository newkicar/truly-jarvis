# v0.1.6（2026-11-22）

维护小版本：发布链路参数化 + 公开发现面（list_profiles）路径归一化 + 测试可移植性。应用行为零变更。

## 发布链路（packaging）
- **build_gui.ps1 版本参数化**：新增 `-Version x.y.z`（默认 0.1.6，正则校验）——runtime-info.txt 版本行、zip 名、sha256 清单名全部改由 `-Version` 驱动，消除 v0.1.5 时代硬编码 0.1.4 的残留；
- **通用一键发布 packaging/release.ps1**（替代逐版本手写的 release_v0.1.x.ps1）：
  - tag 幂等创建 → push main → push tag → 创建/补齐 GitHub Release（notes 自动取 docs/releases/v<version>.md）；
  - 资产上传改用 **PUT uploads.github.com 二进制流**（v0.1.5 实证：fine-grained token 下 base64 POST asset 端点 404），只上传两个预期资产 `jarvis-gui-<v>-win-x64-portable.zip` + `sha256-jarvis-gui-<v>-win-x64-portable`（替代旧脚本 *.exe/*.txt/*.json/*.py 宽 glob），已存在资产按名跳过（幂等）；
  - token 来源优先级：`-Token` > GITHUB_TOKEN > GH_TOKEN > build\gh_cred.txt 的 password 行（不回显）。

## 公开发现面（jarvis 包）
- **list_profiles 路径归一化**：`user_home` / `workspace` 的 str 入参空串/纯空白等同 None（此前 `Path("") == Path(".")` 会退化为相对当前 cwd 的层目录）；Path 对象原样保留，只读语义不变；
- 出口保持窄面：`from jarvis import create_jarvis, list_profiles, ProfileInfo`，不导出 ProfileRegistry。

## 测试
- test_profiles_discovery 去硬编码用户路径（`C:/Users/uida0712/...`）→ 当前用户 profile 下自建目录（`~/jarvis_pytest_disco`，fixture 首帧 rmtree），可用 `JARVIS_TEST_DISCO_BASE` 覆盖；
- 新增 `test_blank_string_paths_eq_none`（空串/空白入参 = None 行为回归）；
- profile 系套件 81 全绿（registry/schema/discovery）。

## 资产
- 便携包：release/jarvis-gui-0.1.6-win-x64-portable.zip（Nuitka 便携版，GUI-only）+ sha256 清单；
- 源码版：git tag v0.1.6。
